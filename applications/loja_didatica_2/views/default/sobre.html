Sobre o projeto

Uma loja de exemplo para estudar a arquitetura MVC do web2py, o banco SQLite e a integração com React.

Arquitetura MVC (web2py)

Model
models/db.py (DAL + Auth + tabelas), models/regras.py (regras de negócio), models/z_dados_iniciais.py (carga inicial)
View
views/layout.html e uma pasta por controller; templates yatl com {{=variavel}}
Controller
default (público/login), cliente, vendedor, operador, admin e api (JSON)
Static
css/loja.css, js/loja.js, js/componentes/*.jsx (React; versões pré-compiladas em compilado/), js/vendor/
Dados
loja.sqlite e imagens/ na pasta do loja_didatica_2_v2.py (fora de applications/)

Fluxo de uma compra

  1. Cliente monta o carrinho (React + api/carrinho_*); o carrinho fica na tabela carrinho_item.
  2. Ao finalizar, criar_pedido_do_carrinho() cria pedido, itens e PIX e baixa o estoque em uma única transação.
  3. A tela do PIX mostra QR Code e "copia e cola" (BR Code com CRC16 válido, chave fictícia).
  4. O cliente clica em "Já paguei"; um operador confirma ou recusa manualmente.
  5. Confirmado, o operador avança a entrega: separando → transportadora → em entrega → entregue.
  6. Cancelamento (do cliente ou por PIX recusado) devolve os itens ao estoque.

Consistência do estoque

Toda alteração passa por registrar_movimento(), que grava um movimento_estoque (entrada, saída, devolução, ajuste). A saída usa um UPDATE ... WHERE estoque >= qtd, que impede estoque negativo mesmo com dois clientes comprando ao mesmo tempo. O administrador confere produto.estoque contra a soma dos movimentos.

Upload de imagens

O vendedor envia qualquer imagem (JPEG, PNG, GIF, WEBP, BMP, TIFF). O servidor valida com o Pillow, corrige a orientação EXIF, remove transparência, recorta ao centro para {{=IMAGEM_W}}×{{=IMAGEM_H}} e gera a miniatura {{=MINI_W}}×{{=MINI_H}}, ambas em JPEG, salvas em imagens/<codigo>.jpg (pasta ao lado do loja_didatica_2_v2.py) e servidas pela action default/imagem.

Segurança (versão didática)

  • Senhas com hash do Auth (PBKDF2); sessão do web2py.
  • Token CSRF único para formulários (_csrf) e API (X-CSRF-Token).
  • Consultas via DAL (sem SQL montado à mão) e escape automático nas views.
  • PIX fictício: a chave {{=CHAVE_PIX_FAKE}} não existe. Nada é cobrado.
